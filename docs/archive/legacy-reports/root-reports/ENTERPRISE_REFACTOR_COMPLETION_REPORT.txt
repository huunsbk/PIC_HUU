BÁO CÁO HOÀN THÀNH MIGRATION KIẾN TRÚC ENTERPRISE

==================================================
TỔNG QUAN
==================================================
Hệ thống tài khoản cũ thông qua JSON `accounts_config` trong bảng `tournament` đã bị xóa sổ hoàn toàn khỏi ứng dụng (source code).
Ứng dụng hiện tại đã được cấu hình trỏ hoàn toàn sang các bảng độc lập theo chuẩn Enterprise (`accounts`, `tenants`, `roles`, `active_sessions`, `login_logs`).

==================================================
PHẦN 1: FILE ĐÃ SỬA
==================================================
1. src/types.ts
   - Thêm cấu trúc bảng: Tenant, AppRole, EnterpriseAccount, ActiveSession, LoginLog.
   - Thêm thuộc tính tenant_id, role_id cho Account cũ (chỉ để tương thích giao diện tạm).
2. src/store.ts
   - Gỡ bỏ mảng accounts và các hàm CRUD cũ (addAccount2, updateAccount2, deleteAccount2).
   - Thêm object `currentEnterpriseUser`.
   - Viết lại hàm `setAuthStatus`: Đăng xuất các session cũ và Insert token đăng nhập vào bảng `active_sessions`. Log đăng nhập vào `login_logs`.
   - Viết lại hàm `checkAdminSession`: Polling trực tiếp từ `active_sessions` thay vì chọc vào `accounts_config` chung.
   - Viết lại hàm `initSupabase`: Kiểm tra phân quyền single-login Enterprise.
   - Viết lại luồng `logout`: Xóa session trong database qua bảng `active_sessions`.
3. src/components/AuthModal.tsx
   - Gỡ bỏ logic loop duyệt accounts cũ.
   - Thay bằng logic trực tiếp SELECT query bảng `accounts` có mapping với `tenants` và `roles`.
   - Xác định `admin1`, `admin2`, `admin3` dựa trên `role_level` trả về từ bảng Role (1, 2, 3).
4. src/components/ScoreEntry.tsx
   - Kiểm tra `permittedEventIds` thông qua array có sẵn ở `currentEnterpriseUser` thay vì lookup trong mảng accounts[] lỗi thời.
5. src/App.tsx
   - Cắt toàn bộ Component `AccountManager.tsx` khỏi Routing và Render Tree.
   - Loại bỏ tab quản lý tài khoản trên giao diện (chỉ dẫn User truy cập Enterprise Dashboard / Database để thêm Account).

- public.roles

- public.accounts
- public.account_event_permissions

INSERT INTO \`active_sessions\`

PHẦN 4: CHỨC NĂNG ĐÃ THAY ĐỔI
==================================================
1. Đăng nhập: Không còn xác thực offline qua mảng JSON. Xác thực qua `supabase.auth.signInWithPassword`, sau đó kéo object Account từ cơ sở dữ liệu để map Role và phân tải Tenant (Khu vực CSDL).
2. Kiểm soát phiên đăng nhập song song (Single-Login): Đăng nhập thiết bị mới sẽ Force Logout thiết bị cũ ở cấp độ Database Row Constraint / Table `active_sessions` chuẩn SaaS. Hàm polling client check token khớp với Row duy nhất.
3. Chặn đăng nhập Tenant ngẫu nhiên: Cắt bỏ khả năng đổi Tenant trái phép trong localStorage; hệ thống tự rà soát nếu URL sai tenant. Doanh nghiệp (tenant) tách biệt 100%.
