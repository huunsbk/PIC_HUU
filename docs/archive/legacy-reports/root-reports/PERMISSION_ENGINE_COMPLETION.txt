BÁO CÁO HOÀN THÀNH PERMISSION ENGINE

==================================================
TỔNG QUAN
==================================================
Tất cả các kiểm tra Role trực tiếp kiểu `if (role === '...')` đã được thay thế hoàn toàn bằng hệ thống kiểm tra Permission (Quyền hạn). 
Hệ thống nay sử dụng table `account_permissions` và mapping permission logic thông qua hàm helper trợ thủ `hasPermission()`.

==================================================
CHI TIẾT THỰC HIỆN
==================================================

1. src/types.ts & src/store.ts (Trạng Thái + Helper)
   - Interface `EnterpriseAccount` nay chứa `permissions?: string[]`.
   - `useTournamentStore` được bổ sung properties `permissions` và helper function `hasPermission(permissionName: string) => boolean`
   - Kí tự đại diện (Wildcard) `*` được hỗ trợ dành cho Master/Super Admin (quản trị toàn quyền hệ thống).

2. src/components/AuthModal.tsx (Load Database)
   - Cập nhật Data Fetching Logic sau khi đăng nhập: Truy xuất song song thông tin từ bảng trung gian `account_permissions` join với bảng `permissions (name)`.
   - Mapping danh sách chuỗi quyền (array of permissions) trực tiếp vào payload đưa cho Redux/Zustand Store.
   - Hỗ trợ Fallback (Trường hợp Server DB Permissions chưa định nghĩa chuẩn thì dựa trên Level Role Map cũ để seed local memory permission).

3. XÓA BỎ HOÀN TOÀN TRỰC TIẾP ROLE CHUYỂN QUA `hasPermission`
   - Navigation (`App.tsx`): 
     Dùng `item.permission` với `hasPermission(item.permission)` thay cho `.roles.includes(userRole)`.
     Ví dụ: `permission: 'manage_teams'`, `permission: 'manage_events'`.
   
   - Bảo mật Routing Header, Tenant Switching (`store.ts`, `App.tsx`):
     Loại bỏ hoàn toàn các object logic `userRole === 'TENANT_ADMIN'` khi xác minh Tenant Switching. Thay bằng xác minh theo `hasPermission('switch_tenant')` + Fallback theo phiên bảo mật có `currentEnterpriseUser`. 
   
   - Permission Specific Cases (`ScoreEntry.tsx`): 
     Hủy lệnh kiểm tra `if (userRole !== 'EVENT_ADMIN')`. Thay bằng `if (hasPermission('*') || hasPermission('manage_events') || hasPermission('manage_tournaments'))`, nếu không thì chạy luồng default của `EVENT_ADMIN` (kiểm tra `permittedEventIds`).

==================================================
KẾT LUẬN
==================================================
Permission Engine đã hoạt động độc lập và đầy đủ. Việc quản lý Access Control giờ cực kì linh hoạt, ứng dụng đã thoát khỏi sự giới hạn của Role-based cổ điển và sử dụng chuẩn RBAC (Role-Based Access Control) + Fine-Grained Permissions theo chuẩn Enterprise SaaS.
